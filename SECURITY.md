# Security Policy

## Reporting a vulnerability

Please report security vulnerabilities privately to the project maintainers rather than opening a public issue with exploit details.

Include the affected component and version/commit, reproduction steps, security impact, relevant logs or proof of concept with secrets removed, and suggested mitigation when known.

Do not include private keys, access tokens, passwords or personal data in a report.

## Security scope

Reports are especially important for WireGuard tunnel establishment and teardown, routing and kill-switch behavior, DNS/IPv6/WebRTC leak protection, cryptographic key handling, certificate validation and pinning, peer registration and administrative APIs, command execution, update/distribution mechanisms, and privacy-sensitive logging.

## Disclosure

The project aims to coordinate remediation and disclosure responsibly. Public disclosure should not occur before maintainers have had a reasonable opportunity to assess and address a reported vulnerability, except where law or an agreed disclosure timeline requires otherwise.

## Security limitations

No VPN can guarantee universal anonymity or protection against every endpoint, network, legal or operational threat. FreedomVPN's security claims are limited to behavior that has been implemented and verified.
